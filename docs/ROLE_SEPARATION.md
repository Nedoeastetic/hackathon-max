# Разделение ролей: Житель и Мастер

## Что изменилось

Теперь интерфейс чётко разделён на две роли:

### 👤 Житель
- **Чат с ботом** — отправка обращений (текст + фото)
- **История заявок** — просмотр всех своих обращений
- **Статусы** — отслеживание выполнения заявок

### 🔧 Мастер
- **Дашборд заявок** — просмотр доступных и своих заявок
- **Фильтры** — доступные / мои / все
- **Действия** — взять заявку, начать работу, выполнить

## Как это работает

### 1. Экран выбора роли
При запуске приложения появляется экран с двумя кнопками:
- **Житель** — для отправки обращений
- **Мастер** — для выполнения заявок

### 2. Интерфейс Жителя
```
┌─────────────────────────────────┐
│ ← Житель          [Чат] [Заявки]│
├─────────────────────────────────┤
│                                 │
│  Чат с ботом                    │
│  • Отправка текста              │
│  • Загрузка фото                │
│  • Уточняющие вопросы           │
│  • Подтверждение заявки         │
│                                 │
└─────────────────────────────────┘
```

**Вкладка "Заявки":**
- Список всех заявок пользователя
- Статусы: Ожидает → Назначена → В работе → Выполнена
- Информация о мастере (если назначен)

### 3. Интерфейс Мастера
```
┌─────────────────────────────────┐
│ ← Мастер Иванов И.И.    [Онлайн]│
│ Сантехник • Рейтинг: 4.8⭐      │
├─────────────────────────────────┤
│ [Доступные] [Мои] [Все]         │
├─────────────────────────────────┤
│                                 │
│  📋 Водоснабжение               │
│  Протечка трубы                 │
│  "Течёт труба в подвале"        │
│  Адрес: ул. Ленина, д. 42       │
│  Срочность: Высокий             │
│  AI уверенность: 94%            │
│                                 │
│  [Взять заявку]                 │
│                                 │
└─────────────────────────────────┘
```

## Workflow

### Сценарий 1: Житель отправляет заявку
1. Житель открывает приложение → выбирает роль "Житель"
2. Отправляет текст/фото в чат
3. Бот анализирует и уточняет детали
4. Житель подтверждает заявку
5. Заявка появляется в истории со статусом "Ожидает"

### Сценарий 2: Мастер берёт заявку
1. Мастер открывает приложение → выбирает роль "Мастер"
2. Видит доступные заявки (фильтр "Доступные")
3. Нажимает "Взять заявку"
4. Статус меняется на "Назначена"
5. Нажимает "Начать работу" → статус "В работе"
6. Нажимает "Выполнено" → статус "Выполнена"

### Сценарий 3: Житель видит выполнение
1. Житель открывает вкладку "Заявки"
2. Видит свою заявку со статусом "Выполнена"
3. Видит имя мастера, который выполнил работу

## Технические детали

### Разделение данных
- **Житель** видит только свои заявки (`userId === 'resident-demo'`)
- **Мастер** видит:
  - Доступные заявки (`status === 'AVAILABLE'`)
  - Свои заявки (`assignedWorker === masterId`)
  - Все заявки (для администратора)

### Статусы заявок
```
AVAILABLE → ASSIGNED → IN_PROGRESS → RESOLVED
   ↑           ↑            ↑            ↑
 Житель    Мастер      Мастер      Мастер
 создаёт   берёт       начинает    завершает
```

### Фильтры мастера
- **Доступные** — заявки без исполнителя
- **Мои** — заявки, которые мастер взял в работу
- **Все** — все заявки в системе

## Преимущества разделения

1. **Чёткая роль** — каждый пользователь видит только то, что ему нужно
2. **Безопасность** — житель не может изменить статус заявки мастера
3. **UX** — интерфейс адаптирован под конкретную задачу
4. **Демонстрация** — легко показать полный workflow на хакатоне

## Демонстрация на хакатоне

### Шаг 1: Показать выбор роли
```
Запускаем приложение → экран выбора роли
```

### Шаг 2: Житель отправляет заявку
```
Выбираем "Житель" → отправляем "Не работает свет" → подтверждаем
```

### Шаг 3: Мастер берёт заявку
```
Возвращаемся к выбору роли → выбираем "Мастер" → видим заявку → берём
```

### Шаг 4: Мастер выполняет работу
```
Начинаем работу → завершаем → заявка выполнена
```

### Шаг 5: Житель видит результат
```
Возвращаемся к "Житель" → вкладка "Заявки" → видим статус "Выполнена"
```
