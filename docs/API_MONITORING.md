# Отслеживание статуса ML API

## Визуальные индикаторы

### 1. Индикатор в заголовке чата
В правом верхнем углу чата жителя отображается статус ML API:

- 🟢 **Зелёный бейдж "ML API"** — API доступен и работает
- 🟠 **Оранжевый бейдж "Симуляция"** — API недоступен, используется локальная симуляция
- ⚪ **Серый бейдж "Проверка..."** — идёт проверка доступности

### 2. Панель статуса в чате
В начале чата отображается информационная панель:

**Если ML API работает:**
```
✅ ML API подключен
Используем реальный ML API для анализа. Прокси-сервер работает.
```

**Если ML API недоступен:**
```
⚠️ Локальная симуляция
Прокси-сервер не запущен. Для использования реального ML API выполните:
node proxy-server.cjs
```

### 3. Переключатель режимов
Рядом с индикатором статуса есть выпадающий список с тремя режимами:

- **Авто** — автоматически использует ML API, если доступен, иначе симуляцию
- **Только API** — принудительно использует только ML API (ошибка, если недоступен)
- **Симуляция** — принудительно использует только локальную симуляцию

### 4. Кнопка проверки
Кнопка 🔍 рядом с переключателем режимов позволяет вручную проверить доступность ML API.

## Логирование в консоли

Откройте DevTools (F12) → вкладка Console для просмотра логов:

### При загрузке страницы:
```
✅ ML API доступен
или
⚠️ ML API недоступен
```

### При анализе текста/фото:
```
✅ Используем ML API через прокси
📝 Text API результат: { category: "WATER_SUPPLY", ... }
📷 Vision API результат: { classificationResult: "KNOWN_INCIDENT", ... }

или

⚠️ Используем локальную симуляцию
```

### При ошибках:
```
❌ Ошибка Text API: Error: ...
❌ Ошибка Vision API: Error: ...
```

## Периодическая проверка

Приложение автоматически проверяет доступность ML API каждые 30 секунд. Если API был недоступен, а потом появился — индикатор обновится автоматически.

## Режимы работы

### Режим "Авто" (по умолчанию)
```
if (ML API доступен) {
  использовать ML API
} else {
  использовать локальную симуляцию
}
```

**Когда использовать:** Для демонстрации — показывает оба режима работы.

### Режим "Только API"
```
if (ML API доступен) {
  использовать ML API
} else {
  показать ошибку
}
```

**Когда использовать:** Когда нужно гарантировать использование реального ML API. Если API недоступен, покажет ошибку с инструкцией по запуску прокси-сервера.

### Режим "Симуляция"
```
всегда использовать локальную симуляцию
```

**Когда использовать:** Для тестирования без зависимости от внешних сервисов.

## Проверка прокси-сервера

### Вручную через curl:
```bash
curl http://localhost:3001/api/health
```

Ожидаемый ответ:
```json
{
  "status": "ok",
  "models": {
    "cv": "cv-v4-2026-09-29",
    "text": "text-v3-2026-09-29"
  }
}
```

### Через браузер:
Откройте http://localhost:3001/api/health в браузере.

## Устранение проблем

### Проблема: Индикатор показывает "Симуляция", хотя прокси запущен

**Решение:**
1. Нажмите кнопку 🔍 для ручной проверки
2. Проверьте консоль браузера на наличие ошибок CORS
3. Убедитесь, что прокси-сервер запущен на порту 3001

### Проблема: Ошибка CORS в консоли

**Решение:**
Прокси-сервер должен запускаться с флагом CORS. Проверьте файл `proxy-server.cjs`:
```javascript
app.use(cors());
```

### Проблема: Режим "Только API" показывает ошибку

**Решение:**
1. Запустите прокси-сервер: `node proxy-server.cjs`
2. Дождитесь сообщения: `🚀 Proxy server running on http://localhost:3001`
3. Нажмите кнопку 🔍 для проверки

## Примеры использования

### Демонстрация на хакатоне

1. **Запустите прокси-сервер:**
   ```bash
   node proxy-server.cjs
   ```

2. **Запустите приложение:**
   ```bash
   npm run dev
   ```

3. **Покажите индикатор:**
   - Укажите на зелёный бейдж "ML API"
   - Объясните, что используется реальный AI

4. **Продемонстрируйте анализ:**
   - Отправьте текст "Не работает свет"
   - Покажите логи в консоли: `📝 Text API результат: ...`
   - Объясните, что анализ выполнен реальным ML API

5. **Покажите fallback:**
   - Остановите прокси-сервер (Ctrl+C)
   - Подождите 30 секунд (автоматическая проверка)
   - Индикатор изменится на "Симуляция"
   - Отправьте текст снова
   - Покажите, что работает локальная симуляция

### Тестирование без VPN

Если ML API недоступен из вашей сети:

1. Переключитесь в режим "Симуляция"
2. Все функции будут работать локально
3. Для демонстрации реального API используйте VPN

## Мониторинг

Для постоянного мониторинга можно добавить:

1. **WebSocket** — для получения уведомлений об изменении статуса в реальном времени
2. **Метрики** — подсчёт успешных/неуспешных запросов к API
3. **Алерты** — уведомления при недоступности API

Но для хакатона текущей реализации достаточно.
